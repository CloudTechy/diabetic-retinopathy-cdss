# Probability calibration (temperature scaling): validation-fitted, test-evaluated

Generated by `backend/scripts/calibrate_probabilities.py`. Every number is read from the JSON and CSV files in this directory.

## 1. Procedure

1. **Fit (validation partition only).** Logits for the 526 validation images were produced with the fixed checkpoint (SHA-256 `67d0b89641f08057126dd411e380b25575ef29f71ae37ee5796d472d9203dbf7`) and written to `validation_predictions.csv`. One scalar $T$ was fitted by minimising the validation multiclass NLL of $\mathrm{softmax}(z/T)$ with `scipy.optimize.minimize_scalar(method='bounded')` on bounds [0.05, 10.0]. No test row was read and no test image was opened in this phase.
2. **Freeze.** $T$ was written to `temperature_scaling_artifact.json` (SHA-256 `2e65e7d61b426a87c613ce1d2590e46057fe4ada5de3a01aef00d8961f27a789`) and copied byte-identically to `backend/models/calibration/temperature_scaling_artifact.json` for the runtime engine.
3. **Evaluate (test partition, 525 images).** Only after the freeze were the test rows read, their logits produced (`test_predictions.csv`), and the frozen $T$ applied once.
4. **Runtime.** The full inference engine, loading the runtime copy of the artifact, graded test images; its served class scores were compared with $\mathrm{softmax}(z/T)$ (section 5).

There is no test-set gate deciding whether to use the fitted $T$: such a gate would select the temperature with test labels.

## 5. Runtime integration

- The inference engine loads `backend/models/calibration/temperature_scaling_artifact.json` (SHA-256 `2e65e7d61b426a87c613ce1d2590e46057fe4ada5de3a01aef00d8961f27a789`) beside the checkpoint and refuses to serve if it is missing, malformed, fitted on a split other than `val`, or fitted for another checkpoint.
- `predict()` returns `class_scores` = $\mathrm{softmax}(z/T)$ - the vector the API's `classScores` and the interface's score card receive - with the raw softmax kept per class as `uncalibratedScore` for audit. The persisted model version reads `EfficientNet-B0-DR-v1 (fixed weights; temperature-scaled T=1.093921, ts-v2)`.
- 25 test images graded through the engine: largest absolute difference between the served vector and $\mathrm{softmax}(z/T)$ from `test_predictions.csv` = 3.76e-07 (tolerance 1e-05). Evidence: `runtime_integration_evidence.json`; automated tests: `backend/tests/test_probability_calibration.py`.

## 6. What shows the test labels were not used to select or optimise $T$

These are checkable properties of the script and artefacts; the claim extends no further than they do.

- `fit_temperature()` receives only validation logits and labels, and refuses any record whose split tag is not `val` (tested).
- Phase 1 reads the manifest filtered to `split == 'val'`; the test rows are first read in phase 2, after the artifact was written. The order of operations is recorded in `leakage_audit.json` and the log.
- The artifact's SHA-256 at freeze time equals its SHA-256 after evaluation: **True**.
- The artifact carries only the keys ['checkpoint', 'created_at_utc', 'fit', 'fit_counts', 'fit_split', 'manifest_sha256', 'method', 'note', 'script', 'temperature', 'validation_ids_sha256', 'version']; none is a test statistic (tested). Its `validation_ids_sha256` names the exact 526 validation images.
- Validation and test image ids are disjoint (overlap 0), and `validation_predictions.csv` contains only `val` rows (tested).
- Refitting from `validation_predictions.csv` alone reproduces the artifact's $T$ (tested), so $T$ is a function of the validation file and nothing else.
- No test-metric gate chooses between $T=1$ and the fitted $T$.

One qualification: the validation partition was also used during training to select the checkpoint epoch (best validation QWK, `training_protocol.md`). Fitting $T$ on it is the standard procedure (Guo et al., 2017), but it means the validation NLL is not an independent estimate; the test-set figures in section 3 are.

## 7. Limitations

- One scalar is fitted; class-wise miscalibration that a single temperature cannot correct is not corrected.
- ECE and MCE depend on the binning; MCE in particular is driven by sparsely populated bins, so both binnings are reported.
- Calibration changes how probabilities are reported. It does not change which grade is predicted and is not a diagnosis.
